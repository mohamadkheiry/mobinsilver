# نمودارهای Activity و وضعیت

## 1. فعالیت مرور تا ثبت سفارش

```mermaid
flowchart TD
    A([شروع]) --> B[ورود به فروشگاه]
    B --> C[مرور، جست‌وجو یا فیلتر]
    C --> D[مشاهده جزئیات محصول]
    D --> E{موجود است؟}
    E -- خیر --> F[نمایش ناموجود و محصولات جایگزین]
    F --> C
    E -- بله --> G[افزودن به سبد]
    G --> H{ادامه خرید؟}
    H -- بله --> C
    H -- خیر --> I[مشاهده سبد]
    I --> J{کاربر وارد است؟}
    J -- خیر --> K[ورود یا ثبت‌نام]
    K --> L{احراز هویت موفق؟}
    L -- خیر --> K
    L -- بله --> M[ورود اطلاعات تحویل]
    J -- بله --> M
    M --> N[ارسال سفارش به API]
    N --> O{اعتبار محصول و موجودی}
    O -- نامعتبر --> P[نمایش خطا و refresh سبد]
    P --> I
    O -- معتبر --> Q[محاسبه مبلغ سمت سرور]
    Q --> R[کاهش موجودی و ذخیره سفارش]
    R --> S[نمایش شماره سفارش]
    S --> T([پایان])
```

## 2. فعالیت ثبت‌نام و ورود

```mermaid
flowchart TD
    A([شروع]) --> B{حساب دارد؟}
    B -- خیر --> C[فرم ثبت‌نام]
    C --> D[اعتبارسنجی اولیه client]
    D --> E[ارسال به API]
    E --> F{ایمیل تکراری؟}
    F -- بله --> G[نمایش پیام کنترل‌شده]
    G --> C
    F -- خیر --> H[Hash رمز با salt]
    H --> I[ایجاد Customer]
    I --> J[صدور JWT]
    B -- بله --> K[فرم ورود]
    K --> L[بررسی credential]
    L --> M{معتبر؟}
    M -- خیر --> N[پاسخ 401 عمومی]
    N --> K
    M -- بله --> J
    J --> O{Role}
    O -- Admin --> P[داشبورد مدیریت]
    O -- Customer --> Q[فروشگاه یا داشبورد مشتری]
    P --> R([پایان])
    Q --> R
```

## 3. فعالیت مدیریت محصول

```mermaid
flowchart TD
    A([مدیر وارد است]) --> B[بخش محصولات]
    B --> C{عملیات}
    C -- ایجاد --> D[تکمیل فرم محصول]
    C -- ویرایش --> E[انتخاب محصول و ویرایش فرم]
    C -- حذف --> F[انتخاب محصول]
    D --> G[اعتبارسنجی نام، slug، دسته، قیمت و موجودی]
    E --> G
    G --> H{معتبر؟}
    H -- خیر --> I[نمایش خطای فیلد]
    I --> C
    H -- بله --> J[ارسال POST یا PUT]
    J --> K{موفق؟}
    K -- خیر --> L[نمایش خطای API و حفظ فرم]
    L --> C
    K -- بله --> M[refresh فهرست]
    F --> N{تأیید حذف؟}
    N -- خیر --> B
    N -- بله --> O[ارسال DELETE]
    O --> M
    M --> B
```

## 4. فعالیت تغییر وضعیت سفارش

```mermaid
flowchart TD
    A([ورود مدیر]) --> B[مشاهده سفارش‌ها]
    B --> C[انتخاب سفارش]
    C --> D[مشاهده وضعیت و اقلام]
    D --> E[انتخاب وضعیت بعدی]
    E --> F{transition مجاز؟}
    F -- خیر --> G[رد تغییر و نمایش دلیل]
    G --> D
    F -- بله --> H[ذخیره وضعیت و Audit Log آینده]
    H --> I[به‌روزرسانی داشبورد مشتری]
    I --> J[ارسال اعلان آینده]
    J --> K([پایان])
```

در نسخه جاری کنترل role و ذخیره وضعیت وجود دارد، اما whitelist transition، Audit Log و اعلان هنوز باید اضافه شوند.

## 5. نمودار وضعیت سفارش

```mermaid
stateDiagram-v2
    [*] --> Pending: ثبت سفارش
    Pending: در انتظار بررسی
    Paid: پرداخت شده
    Preparing: در حال آماده‌سازی
    Shipped: ارسال شده
    Delivered: تحویل شده
    Cancelled: لغو شده

    Pending --> Paid: تأیید پرداخت
    Pending --> Cancelled: رد یا انصراف
    Paid --> Preparing: شروع پردازش
    Paid --> Cancelled: بازپرداخت و لغو
    Preparing --> Shipped: تحویل به حمل‌ونقل
    Preparing --> Cancelled: توقف و بازپرداخت
    Shipped --> Delivered: تأیید تحویل
    Delivered --> [*]
    Cancelled --> [*]
```

این ماشین وضعیت، طراحی هدف است. در نسخه فعلی status رشته‌ای است و مدیر می‌تواند مقدار را تغییر دهد؛ پیاده‌سازی transition guard یکی از اقدامات اولویت‌دار است.

## 6. فعالیت پرداخت امن آینده

```mermaid
flowchart TD
    A[سفارش Pending ایجاد شد] --> B[ایجاد Payment Attempt با Idempotency Key]
    B --> C[ارسال کاربر به درگاه]
    C --> D{نتیجه ظاهری مرورگر}
    D -- لغو یا شکست --> E[نمایش ناموفق؛ سفارش Pending]
    D -- بازگشت موفق --> F[انتظار برای verify سمت سرور]
    F --> G[ارسال verify به درگاه]
    G --> H{امضا، مبلغ، شناسه و وضعیت معتبر؟}
    H -- خیر --> I[ثبت رخداد و عدم تغییر مالی]
    H -- بله --> J{قبلاً پردازش شده؟}
    J -- بله --> K[بازگرداندن نتیجه قبلی]
    J -- خیر --> L[ثبت Payment موفق]
    L --> M[تغییر سفارش به Paid]
    M --> N[ارسال اعلان]
```

## 7. فعالیت رسیدگی به رخداد Production

```mermaid
flowchart TD
    A[Alert یا گزارش مشتری] --> B[ثبت Incident و زمان شروع]
    B --> C[تعیین Severity و Incident Commander]
    C --> D{اثر بر امنیت یا پرداخت؟}
    D -- بله --> E[محدودسازی فوری و اطلاع تیم مسئول]
    D -- خیر --> F[جمع‌آوری log، metric و trace]
    E --> F
    F --> G{راهکار کم‌ریسک موجود؟}
    G -- rollback --> H[بازگشت به نسخه سالم]
    G -- feature flag --> I[غیرفعال‌سازی قابلیت]
    G -- fix forward --> J[اصلاح اضطراری با review]
    H --> K[Smoke Test]
    I --> K
    J --> K
    K --> L{سرویس پایدار؟}
    L -- خیر --> F
    L -- بله --> M[اعلام رفع و مانیتورینگ]
    M --> N[Postmortem بدون سرزنش]
```
