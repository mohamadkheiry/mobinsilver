# گزارش رگرسیون و سخت‌سازی v4

این گزارش چرخهٔ بازبینی پس از نسخه v3 را ثبت می‌کند. هدف، یافتن خطاهای قابل بازتولید در مسیرهای عمومی، مشتری، مدیر، API، امنیت وابستگی‌ها و رفتار responsive بود.

## چرخه ۱: نشست، سبد و حالت‌های خطا

- route محافظت‌شده تا پایان اعتبارسنجی token هیچ محتوای مشتری/مدیر را نمایش نمی‌دهد.
- token منقضی یا نامعتبر پاک می‌شود و کاربر به ورود هدایت می‌شود.
- سبد localStorage در بارگذاری sanitize می‌شود و قیمت، موجودی و مشخصات محصول را از API تازه می‌کند.
- تعداد سبد به موجودی جدید محدود و محصول نامعتبر یا ناموجود حذف می‌شود.
- خطای دریافت مقالات از حالت «نتیجه‌ای پیدا نشد» جدا و retry قابل استفاده اضافه شد.

## چرخه ۲: فروشگاه و ناوبری

- شمارش دسته‌ها از مجموعه کامل محصولات محاسبه می‌شود و با فیلتر جاری تغییر کاذب نمی‌کند.
- category نامعتبر به `all` نرمال می‌شود.
- تنها لینک دارای query دسته جاری در ناوبری active می‌شود.
- عنوان صفحه جزئیات محصول با نام محصول تنظیم می‌شود.
- شکست مستقل API مقالات باعث ناپدیدشدن محصولات صفحه اصلی نمی‌شود.

## چرخه ۳: سفارش، موجودی و گزارش مالی

- تعداد هر ردیف و مجموع ردیف‌های تکراری بین ۱ تا ۱۰۰ محدود است؛ overflow عددی پیش از تبدیل رد می‌شود.
- ردیف‌های تکراری محصول در یک قلم سفارش ادغام می‌شوند.
- رزرو موجودی با update شرطی و تراکنش serializable انجام می‌شود؛ رقابت روی آخرین موجودی به oversell منجر نمی‌شود.
- فروش و نمودار مدیر فقط وضعیت‌های پرداخت‌شده، در حال آماده‌سازی، ارسال‌شده و تحویل‌شده را جمع می‌زند.
- transition وضعیت سفارش سمت API و UI محدود است؛ سفارش تحویل‌شده یا لغوشده terminal است.

## چرخه ۴: سخت‌سازی API و زنجیره تأمین

- Production کلید JWT پیش‌فرض یا کوتاه‌تر از ۳۲ بایت را رد می‌کند.
- ایجاد مدیر نخست در Production به secret صریح `BootstrapAdmin__Password` نیاز دارد.
- forwarded header فقط از پراکسی‌های شناخته‌شده پذیرفته می‌شود.
- CORS production فقط origin امن دامنه را می‌پذیرد.
- مسیر asset خارجی، traversal، backslash و double-slash رد می‌شود.
- `SQLitePCLRaw.bundle_e_sqlite3` روی نسخه اصلاح‌شده `2.1.13` قفل شد؛ ممیزی NuGet بسته آسیب‌پذیر گزارش نمی‌دهد.
- CI در صورت مشاهدهٔ گزارش بسته آسیب‌پذیر NuGet شکست می‌خورد.

## چرخه ۵: رگرسیون و کنترل دیداری

| کنترل | نتیجه مورد پذیرش |
|---|---|
| `dotnet build -c Release` | ۰ خطا، ۰ هشدار |
| `dotnet list ... --vulnerable --include-transitive` | بدون بسته آسیب‌پذیر |
| `npm run build` | موفق |
| `npm audit --omit=dev` | ۰ آسیب‌پذیری |
| `npm run test:e2e` | ۱۶ از ۱۶ موفق |
| فروشگاه دسکتاپ | تصویرها سالم، active link یکتا، Console بدون خطا |
| موبایل `390×844` | بدون overflow، منو و backdrop قابل استفاده |

## سناریوهای رگرسیون افزوده‌شده

1. شمارش سراسری دسته، deep-link و active link یکتا
2. جلوگیری از نمایش داشبورد با session ذخیره‌شده نامعتبر
3. همگام‌سازی سبد قدیمی با قیمت/موجودی جدید
4. نمایش خطای واقعی API وبلاگ و امکان تلاش مجدد
5. کران تعداد سفارش، عدم oversell و تجمیع ردیف تکراری
6. حذف سفارش pending/cancelled از درآمد
7. رد transition غیرمجاز و terminal بودن وضعیت نهایی
8. رد مسیر asset خارجی و traversal

## محدودیت دامنه آزمون

این دروازه کیفیت خطاهای قابل بازتولید در کد موجود و مسیرهای بالا را پوشش می‌دهد؛ درگاه پرداخت، پیامک، سرویس قیمت لحظه‌ای و چند-instance هنوز یکپارچه نشده‌اند و باید هنگام اضافه‌شدن با تست قرارداد، idempotency و بار جداگانه پوشش داده شوند.
